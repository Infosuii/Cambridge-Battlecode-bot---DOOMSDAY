# I-60-04: conversion fix (collected gems not banked)  [area: economy and banking]

## Problem (analysis/J017.md)
47% of x1c1's 116 ladder losses are conversion losses: 36 losses had >= 1000 collected net of gems lost, i.e. enough
to win if banked (Claudus adgato_gemcombat4: 1107 collected, 210 banked; 0xDEADBEEF adgato_gemcombat5 1093 / 659;
Borufeczki 00great_wall 1370 / 928). Reproduces locally: x1 vs x2 adgato-gemcombat5 collected 1092 / banked 322 and
854 / 203; at R250 434 collected, 84 banked.

## What the bank code does (bot.cpp tribute_if_needed)
Bank when the bag >= kTributeCarry (APEX_TRIBUTE_CARRY 72, set unconditionally in the profile block, so not
--set-able), or the altar is near, or a threat is near with >= 20, or endgame (APEX_END_BANK 600: either score >= 600),
or "wins" (own score + bag >= 1000). The bank-rhythm rule (APEX_BANK_RATIO: bank when dist x ratio <= bag) is off.
A2_ALTARFIX bit 2 (on) stops banking 80 rounds for a carrier stuck 20 turns.
Diagnostic (X1_G60_BANKLOG, gemcombat3/4/5 vs x2): **no stuck-carrier stops at all**; single champions carry 98-245
gems at R250 (a gem-cluster capture jumps the bag far past 72), and a 245 bag needs a 25-round channel. In the lost
game the opponent banks 357 by R200 vs our 84, 917 by R400 vs our 203.

## Mechanism candidates, screened first on the conversion set (5 adgato + 02tangle + 00rushbait-v2, x2 + v86h, 28 games)
- APEX_BANK_RATIO 1 / 2 / 3 on P4 (existing knob: bank smaller bags when the altar is close relative to the bag);
- plan 7 (fast bank, carry x 0.6) from R0 on x1;
- if neither: an X1_G60 code switch for a race rule (bank once the enemy's banked score passes T, or the bag is
  above N with a short trip) and a carry cap on gem-only maps.
Then the full gate (x2, x2-s2, v86h, v81hl, x1bru; ladder + styled + maze) with the sign test.
