# I-60-01: walking-distance camp fields ready from round 1 (draft-time precompute)  [area: maze weaknesses]

## Problem
x1 wins 41% on maze maps vs 49% on ladder (pc/msgs/0010; J014: x1 vs x2 59/116 set A, 63/120 set B). Camp choice
(bot.cpp score_groups -> `travel`) uses the walking-distance field of a group when it exists and falls back to
straight-line Chebyshev distance otherwise (bot.cpp ~1226). Under APEX_DET (on) fields are built at a fixed quota:
2 x APEX_DET_FIELDS on the first turn, APEX_DET_FIELDS per calm turn, **none while an enemy is in view**
(build_fields, bot.cpp ~6650). On maze maps (up to 34 groups a half on set A) many groups have no field for many
early rounds, so early camp targets are ranked by straight-line distance, which on a maze can be several times the
walk (Agent 2 E60: walk / straight-line ratios up to 3.2 on official maps; mazes are designed for this).

Evidence step 1 (before code): diagnostic build (X1_G60_FIELDLOG) printing the round at which fields_ready() first
holds and the share of score_groups travel() calls that fell back to Chebyshev, on ladder vs maze sets A + B.
The idea goes ahead only if mazes show a long fallback window.

## Mechanism
The draft turns run in the same Bot instance as the game (main.cpp), and the first draft turn has 10M fuel (one
field is 3k-33k; all groups 0.1-0.6M, Agent 2 E60). `X1_G60_DRAFTFIELDS`: on the first draft turn, run
World::init() and build every group field plus the altar / enemy fields while fuel_remaining() stays above a
reserve (anytime: stop at the reserve, the normal quota builds the rest). At game init, A2_BRIDGES (dash champions)
changes the field graph, so for a dash champion the prebuilt fields are discarded and rebuilt as today (no gain,
no harm). No new randomness; replays stay exact.

## Expected fuel cost
Draft turn only (10M budget; spend <= ~3M). Zero change to play-turn fuel, so no new fuel-outs expected; possibly
fewer (fewer field builds during play).
