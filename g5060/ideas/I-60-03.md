# I-60-03: the gate's noise floor (method, for every area)

## Problem
Verdicts move by +-10..25 wins of 716 when the base changes (J013: +27 vs x1 became -7 vs bp; J016: features that
passed alone lose on p4). A code change that alters fuel use by a few instructions reshuffles most games (446-603 of
716 changed in J013 / J016) with no change in behaviour, so part of every delta is chaos. Nobody has measured how big.

## Mechanism (measurement, not a feature)
`X1_G60_NOISE=N` (bots/x1g60, off = 1746f2bb7fa3): N no-op volatile steps at the start of each turn. Decisions are
identical; only fuel use shifts, so fuel-dependent branches (field quotas, search budgets, room() guards) diverge and
games reshuffle as they do after a real change. Four builds (N = 1, 2, 3, 5) on top of P4, full gate (716 games).
Their deltas vs p4 are draws from the null distribution: the spread says how large a gain must be before it is real.

## Fuel
A few fuel per turn. No new fuel-outs expected beyond reshuffling.

## Output
results/I-60-03.md: delta, kind deltas and games-changed per noise build; proposed threshold (e.g. a gain must exceed
the largest null |delta|, or a 2-sigma band) for the PC to adopt or not.
