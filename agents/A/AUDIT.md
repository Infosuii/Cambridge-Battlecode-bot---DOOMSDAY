## 1. SDK facts (summary; details + line references in `sdk_facts.json`)

Runtime values were read through the SDK by a probe bot (`agents/A/probe/a_sdk_dump.cpp`, one official `--release` match
on 00ambush; raw records `evidence/sdk_probe_facts.jsonl`). They are engine-provided and may change with the engine: read
`bc::constants::*` at runtime.

- Game: `winning_gems` 1000, `max_rounds` 2000 (`cambc.h:110-113`). Tiebreak rule after 2000 rounds is **not documented**;
  observed: 01boss-battle original vs original 0-0 at round 2000 -> `teamB`. Summary JSON: `match.outcome`, `roundsStarted`,
  `seed` (per map), `teams[].submittedGems`, `champions[].metrics` (17 metrics), timelines, events incl. `fuelExhausted`.
- Settings: capture 5, camp sleep 2, respawn 60, recall 5 (home emblem: 3), submit range 1 (Chebyshev), submit duration
  multiplier 0.1/gem (min 1), kill gold 100, assist gold 0, passive gold 0, spawn healing 1.0 (full heal per round on spawn).
- Champions: 13 physical types, 12 draft picks (Cassi+Issac one pick, linked death). Two ability slots each; every
  ability has max cooldown 8 rounds; ABI `max_charges` is 0 everywhere (no charges in practice). Melee range 1, ranged 3,
  vision 8, move speed 1 for all. Per-champion stats/abilities (kind, range, radius, modifier, duration, target set,
  exclusive-with-movement) are in `sdk_facts.json` and match the original's `kBase` table (`A2_KITFIX & 16`).
- Rules exposed as errors: one move, one basic attack (attack_reset restores it), one cast per turn; casting and moving
  are exclusive for abilities flagged `exclusive_with_movement`; stun prevents actions and interrupts channels.
- Camps: wolf 1350/20 range 3, elk 2400/60 r4, gem/gold cluster 120/0, monolith 20000/200 r5, golem 5000/120 r4. Group
  rewards (gold, gems) after capture; groups respawn.
- Wards: one active ward per champion (`active_wards` 1), recharge 10 rounds, unlimited lifetime, placement radius 2,
  vision 6. Control-ward radii exist in the raw settings but there is **no control-ward API** in this SDK.
- Items: 42 = 7 families (monster, power, durability, treasure, jungle, home, bruiser) x 3 stats x shard/emblem. Shards
  30 gold, purchasable; emblems (150) only by combining 5 shards; emblem passives: monster +10% camp damage, durability
  -10% damage taken, treasure +20% gold, jungle -30% camp damage taken, home recall 3 turn ends; power/bruiser emblems
  count as extra stats. Buying only on spawn or while dead (Tavi: anywhere; Tavi sells, on spawn, full refund). Inventory
  size is not exposed (only an `inventory_full` error).
- Consumables: tp_crystal (10 g, carry 1, 3-round channel, flash within 3), altar_lock (10 g, carry 1, on an altar within 2,
  5 hits to destroy, blocks enemy tributes). Raw ABI ids {0, 2}; id 1 = retired scroll.
- Memory: shared memory **8 bytes per team**, draft memory **1024 bytes** (writable only during the draft; champions
  read a startup snapshot). The draft and each champion run as separate guests: process memory is per champion.
- Visibility: all champion handles, types, teams and alive state are readable without vision; position, hp, stats,
  state, buffs, cooldowns, carried gems, items only while visible; enemy gold never; submitted gems of both teams always.
- Fuel: `fuel_remaining()`; first draft turn 10x, first champion turn 2x; `debug_block` free only in debug builds.
  **printf costs about 65 fuel per output character** (the probe's 937,830-fuel first draft turn ran out after ~14 KB),
  so every logging path (training records, telemetry) has to be costed. The bundle's `team-<x>.fuel` member is a
  per-turn fuel trace.

Notes on the main hooks:
- **objective**: candidates are the post-route-search top-K of `score_groups` (captured right before `return best`);
  the substitution point is `farm()` before `if (best != target_group)`, so the claim write and every legality check
  stay. The capture self-test found the committed `target_group` equal to the captured teacher choice on every farm turn.
- **strategy**: the chain decides by acting (each behaviour mutates state and issues actions), so the teacher's choice
  is only known afterwards. Candidate 0 = "run the teacher chain", alternatives = force one behaviour first; the
  captured branch (`nnt::Turn::chain`) is the label.
- **bank**: the verdict `go` and all its terms are captured at its definition; substitution right after it keeps the
  walk/submit/lock code.
- **engage**: preferred hook is the final `(winning, in_danger)` pair before `if (tune::kTribDeny & 2)`; the search
  verdict (`tactical_decide`) and the formula verdict are captured separately. `team_decide` is inactive.
- **combat / move / ward / shop / draft_pick**: candidate arrays already exist in the code (sorted neighbour steps,
  dash landings, spell slots, bush tiles, build steps, net scores); hooks sit between the ordering and the execution
  loop, which keeps the original fall-through on refused actions.

## 6. How the v50 camp-net integration perturbed the teacher (source reading)

`references/v50-src/common.h:1` sets `A2_CAMPNET 1`. Inside the `score_groups` scoring loop (v50 `bot.cpp:5150`) every
scored group got a `CnCand` with 18 features (camp type counts over the group, enemy-within-6 and ally-within-4 scans)
**before** the route-search fuel gate (`fuel > kRouteFuel`) and the kDet scoring cap that follow; `campnet_pick`
(v50 `bot.cpp:4693`, called at 5188 after route search) then added sorting, the net and `lab::cn_log` writes (4746).
So even with zero weights the teacher saw less fuel at its own gates and could change route-search admission and
scoring depth - consistent with DIAGNOSIS.md section 2 (zero residual 38/80, campnet-off restores symmetry). The hooks
in this inventory are placed after those gates for this reason (INVARIANTS I3).
