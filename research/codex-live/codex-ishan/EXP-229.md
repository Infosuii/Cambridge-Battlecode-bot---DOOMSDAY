# EXP-229 — Dependency-checked reuse of invariant feature-row fields

Status:HYPOTHESIS; verify dependencies and cost before implementation.

Evidence: EXP222 attributes8284fuel to ten camp rows after the static geometry cache already hits. Those rows contain both invariant design/group fields and dynamic state:positions,walking fields,health,claims,allies and sighting age. Treating the whole row as static is false. EXP208's production deficit does not establish a private target error; EXP223's confirmation is too small for new tuning.

Potential mechanism: cache only explicitly dependency-tagged raw/quantized fields whose exact source values are unchanged,then assemble the same complete input tensor. Keys must include actual source values/design identity/travel-field generation as needed; any unknown or changed dependency falls back to the existing calculation. Preserve q/clamp/rounding semantics,feature order and all dynamic neighbour/claim checks. Do not skip a source read unless its lifetime is established from SDK/code,or use stale group health as a shortcut.

Prerequisite: charged per-field cost census and broad sequential byte-equality against original tensors/logits,covering respawns,captures,bridges,gear/health/claim changes and cache invalidation. No new policy threshold or outcome-selected map cache. Expected gain unknown and possibly small; reject if validation/assembly cost dominates. A preserved tensor does not itself prove full-game identity under fuel guards; a new release must pass all-off/duplicate builds,normal native safety and noisy multi-style gates.
