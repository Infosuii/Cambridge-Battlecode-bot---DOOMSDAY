The split profile on 16 conformance maps, both sides versus v92 and x3inv, finds 56 of 92 logged fuel crossings inside proactive ward selection. None were attributed to the post-placement world refresh. Native statistics counted 105 fuel-outs in the charged build, so 13 were not represented as logged crossings. See [the trace](RUNTIME_WARD_SPLIT.json).

The current coverage loop labels every bush with an allied ward before looking at local placement tiles. It retains only the first 16 ward positions in bushes. Label all local placement components first, and then read the existing labels at those first 16 ward positions. A still-unlabelled ward is necessarily outside all successfully labelled local components. Count that position toward the same cap but use a nonmatching sentinel. Preserve position order, duplicate entries, placement scores and the existing admission check. The no-ward path still calls the original local selector.

The placement set is equivalent given completed labelling and unchanged observations. Unrelated components are now lazy, and component numbers may be assigned in a different order. This can change later fuel and state in consumers such as tactical search. The whole-match safety screen is decisive.

Prediction: fewer proactive ward suspensions on development maps. Before L1, independently rebuild twice, verify switch-off matches v92, and run all 172 pinned local pool cells. Reject on any fault, diagnostic or per-cell increase in fuel-outs. Keep the competition, selection and holdout gates fixed.
