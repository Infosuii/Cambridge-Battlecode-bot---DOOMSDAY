# EXP-055 — Reuse the static siege opacity bitboard

Two independent exact stress cases suspend before a siege move at Cassi R315 and Marcella R458. The movement diagnostic resumes their siege path in the next engine round. Three other stress maps used `greedy_step` in siege with only about 2,000 fuel remaining. A separate charged phase shows an initial siege setup consuming about 40,000 fuel. These are development observations and do not prove every siege suspension comes from the same operation.

Cache the immutable union of walls and bushes as one bitboard when the first siege needs it. The existing opacity table contains exactly that union after it completes. Read the same bit at each existing ray step and keep out-of-bounds handling, ray rounding, mask union, camp order and the original LOS fuel check. This removes the repeated row-by-row expansion. The existing behavior while the linear table is still incomplete may change because the equivalent mask becomes available sooner.

Test this change on the exact EXP-052 base independently of EXP-054. Require the two registered native siege suspensions to disappear on the frozen 26 stress cases, fewer total suspensions, no cell increase and zero faults or codes. Require clean reproducibility and switch-off byte identity before the unchanged official-pool screen. The actual pool case identities and outcomes are outside this design.
